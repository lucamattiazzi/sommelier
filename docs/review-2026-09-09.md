# Sommelier repository review — 9 September 2026

## Outcome

The repository now implements remembered, named terminal associations and authenticated end-to-end
encrypted WebSocket transport. Workbook RPC remains independently versioned and validated at the
endpoints. The default hosted relay rejects the former plaintext pairing flow.

See [the architecture and threat model](secure-pairing.md), [asset inventory](marketplace-assets.md)
and [manual Office test guide](pair-testing.md).

## Corrected findings

- The old relay deserialized cells, prompts, replies and tool results as plaintext RPC. The default
  application now encrypts all application traffic and validates only public framing on the relay.
- Expiring URLs forced repeated copy/paste. The pane saves mutually authenticated identities and
  the bridge saves named profiles; both can reconnect after pane closure or relay restart.
- Raw server presence used to mean “connected.” The pane now waits for a cryptographic peer proof.
- Setup instructions and the skill disagreed about a second chat approval. The skill now delegates
  approval to Excel's existing preview/commit gate. Write-approval waivers are cleared on peer loss.
- Bridge clients could hang after their local control socket closed without a response. They now
  fail promptly instead of keeping a request timer alive.
- Keyboard focus could escape an approval into background controls. Approval and question dialogs
  now focus their first control, trap Tab navigation, support Escape and restore prior focus.
- The context panel inherited a light foreground on a light background; checkbox widths inherited
  text-input sizing. Both are corrected, with better focus/disabled states and reduced motion.
- Terminal settings are collapsed when connected, leaving more room for the workbook conversation.
- The manifest reused one 80 px asset for all dimensions and linked support to the task pane.
  It now references distinct correctly sized icons and a real troubleshooting page.
- The static server served manifest XML as generic binary and cached non-versioned assets forever.
  XML now has the correct MIME type; only fingerprinted JS/CSS assets receive immutable caching.
- Production dependency audit identified vulnerable `ws` and `js-yaml` resolutions. The relay/CLI
  now use ws 8.21.0 and the lockfile resolves patched js-yaml. Development Vite/Vitest dependencies
  are also updated to patched versions; see the lockfile for the exact resolved graph.

## Verification

Environment: macOS, Node.js 24.19.0, pnpm 11.21.0, Vitest 4.1.11. All workbook data used in tests is synthetic.

- 82 focused tests across 21 files cover encrypted framing, wrong keys, tampering, replay,
  reflection, large payloads, reconnect after relay restart, distinct client origin/CORS, duplicate
  roles, RPC, approvals, conflict handling, undo, direct-agent settings and manifest generation.
- The installer test installs self-contained skills into isolated personal directories for
  OpenCode, Codex, Claude Code and Pi, and executes their local bridge entry points.
- A Chromium test drives the built pane at 320 px: first association, encrypted chat, range read,
  preview, keyboard-accessible approval, write/read-back, pane reload, manual reconnect, optional
  automatic reconnect, waiver reset and Forget. It checks no horizontal overflow or browser errors.
- The browser test also checks non-empty HTTP delivery of help pages, stylesheet, manifest, all
  icon dimensions, bridge source and its generated encryption module.
- `pnpm audit` reports no known vulnerabilities across production and development dependencies.
- Targeted type checks, builds and Biome checks pass for the changed packages/files. Development
  manifest generation and deterministic checking pass. The portable skill validator passes.

Reproduce:

```sh
pnpm install --frozen-lockfile
pnpm sommelier:build
pnpm test:pairing
pnpm exec vitest run packages/config/src/manifest.test.ts packages/core packages/agent-http
pnpm test:harness
pnpm exec playwright install chromium
pnpm test:browser
pnpm manifest:check
pnpm audit
```

Browser screenshots are generated in `artifacts/pair-review` (ignored by Git). There are no real
workbook contents, pairing credentials or model keys in those screenshots.

## Not established by these checks

Excel was not found in `/Applications` or the local application index. The browser test exercises
the synthetic adapter, not Office.js, Excel recalculation, protected sheets or platform-specific
webviews. Real Excel and live model/harness sessions remain to be tested. The local Pi executable
reports 0.84.3, but the note “MyPy” has not been confirmed as Pi by the user.

The skill installer is validated, not every harness's long-running behavior or autonomous wakeup.
A skill requires its agent to keep consuming messages. No model provider was called in this review.
No npm release, live deployment or AppSource submission was performed. Publisher/domain/contact
information, final marketplace screenshots and Windows ACL verification remain release work.

Encryption still requires trusted endpoint code. Host the pane separately from an untrusted relay
using `SOMMELIER_ADDIN_ORIGIN` and `VITE_PAIR_RELAY_ORIGIN`; encryption alone cannot protect secrets from
malicious client code. The current PSK protocol has no forward secrecy or independent crypto audit.
The initial setup is model-visible if the user pastes its secret into a model-backed harness.
